# 7-Zip GPO Deployment — PowerShell, MSI, SYSVOL и RDS

[English](README.md) · [История изменений](CHANGELOG.ru.md) · [Инструкция GPO](docs/gpo-setup.ru.md)

Практический пример централизованной установки и обновления **7-Zip 26.04** через Group Policy Preferences (GPP), задачи планировщика Windows под **NT AUTHORITY\SYSTEM**, PowerShell 5.1 и `msiexec.exe`.

Репозиторий создан на основе сохранённых файлов октябрьского внедрения 2026 года. Файлы в `history/` и `scripts/` — **обезличенные адаптации**, а не неизменённые производственные копии.

**Не запускайте скрипты без адаптации.** UNC-путь `ad.example.com` вымышленный, значения SHA256 в `examples/` намеренно недействительны. В скрипты добавлен запрет исполнения при оставленном примере домена. Модифицированные публичные версии после обезличивания не тестировались на Windows.

## Структура

| Путь | Назначение |
| --- | --- |
| `scripts/Install-7Zip.ps1` | Адаптация рабочего установщика v1.1: MSI, проверка версии, SHA256, общий mutex |
| `scripts/Install-7Zip-RDS.ps1` | Отдельная защита RDS: откладывает установку, пока существуют пользовательские сеансы |
| `scripts/7Zip-Diagnostics.ps1` | Чтение версии, задач и локальных журналов без изменений системы |
| `scripts/Compare-SysvolFiles.ps1` | Сравнение контрольных сумм скрипта на двух и более DC |
| `history/` | Сохранённая версия до mutex, v1.1, RDS v1.0 и ранний манифест |
| `examples/manifest.example.json` | Финальная структура манифеста (с демонстрационными SHA256) |
| `docs/` | Развёртывание GPO, эксплуатация, анализ SYSVOL/DFSR |

## Архитектура

```text
AD / GPO -> GPP Scheduled Tasks (LOCAL SYSTEM)
                |-- Initial install --|
                |-- Daily update -----|--> Install-7Zip.ps1
                                     |      |-- Global mutex (15 min)
                                     |      |-- manifest + architecture
                                     |      |-- installed version / 7z processes
                                     |      |-- download + SHA256
                                     |      '-- msiexec /qn /norestart /L*v
                '-- RDS task -> WTS session guard -> installer if no sessions

AD DC1 / DC2 -> SYSVOL/NETLOGON: verify identical script content
```

## Подтверждённые свойства скриптов

- Обе задачи установки/обновления используют **один и тот же mutex** (`Global\Example-7Zip-Deploy` в публичном примере).
- Установка пропускается, если обнаружена версия не ниже целевой, либо откладывается, если работают `7z.exe`, `7zFM.exe` или `7zG.exe`.
- Выбирается MSI для архитектуры ОС, а копия пакета проверяется по SHA256 из манифеста.
- `msiexec` работает без интерактивного интерфейса и без автоматической перезагрузки; коды `0` и `3010` принимаются, необходимость перезагрузки пишется в лог.
- Для RDS WTS API проверяет в том числе **отключённые пользовательские сессии**, а не только активно подключённые. При наличии сеансов обновление откладывается.

**Ограничения:** отложенная установка возвращает `0` и внешне выглядит как успешный запуск задания. Это не доказательство установки. Хеш рядом с MSI обеспечивает контроль согласованности, но не защищает от атакующего, который имеет право заменить и MSI, и манифест. На машине с несколькими установленными копиями 7-Zip скрипт ориентируется на *максимальную* обнаруженную версию, поэтому для полной инвентаризации проверьте обе архитектуры отдельно.

## Реальный кейс и проверка SYSVOL

В ходе внедрения встречались несовпадение SHA256, отсутствие задачи из-за привязки GPO не к тому OU и две версии скрипта на разных DC (**2 181 / 3 693 байта**). `repadmin /replsummary` показывает репликацию Active Directory, **но не доказывает тождественность файлов SYSVOL**. Для проверки используйте `scripts/Compare-SysvolFiles.ps1` и отдельно изучайте состояние DFSR.

Загруженный файл `dfsr-test-20261012-104855.txt` содержит **только контрольный маркер** с отметкой времени и именем DC; это не журнал успешной репликации. Его содержимое намеренно не публикуется.
